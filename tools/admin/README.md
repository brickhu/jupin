# tools/admin —— 本地内容管理台

```bash
pnpm admin                 # → http://127.0.0.1:4983
pnpm admin -- --port 4984  # 换端口
```

句库管理：**列表 / 搜索 / 新增 / 编辑 / 发布**。

## 编辑模型：行内改、草稿留在本地、**一个**「更新」按钮

句子详情页是**唯一**的编辑入口（抽屉只用来**新增**，见下）：

* 每一行信息右侧一个 `✎` —— 点了就地变输入框，输入框后面跟一个 **yes**：
  `yes`（或回车）才提交；**Esc / 点输入框外面（失焦）都是取消** ——
  既然失焦就等于取消，就不需要再放一个 no（多余的第二条路）。
  **译文、状态、难度、标签**能改；
* 改动**先攒着**：底部一个「更新」按钮，**有改动才亮**（还会显示改了几项），
  没改动是禁用的；点它一次把所有改动合成**一个** `PUT` 提交；
* 旁边一个「恢复」把攒下的改动丢掉、回到服务端当前的值（只改了几项时不用去逐项改回来）。

⚠️ **句子 id 与发布时间没有 `✎`**：

* 句子 id = `sha256(正文)` 的前 16 位（64 bit），它同时是文件名和音频路径 ——
  改它就不是「编辑这一条」，
  而是另一条内容了；
* 发布时间 = **「这条什么时候上的线」**，只由服务端在**草稿 → 发布**那一刻写。
  能手改的话它就不再有这个含义（「最后一次编辑」是另一件事，真需要就另加一列）。
  `PUT` 里对 `publishedAt` 是**明确拒收**（400 + 原因），不是静默忽略 ——
  免得有人加了字段却发现「怎么改了没反应」。

⚠️ **攒下的改动会写进 `localStorage`**（键 `jushuo_admin_detail_draft_v1`，
按 `<env>:<id>` 分桶）—— 刷新/关掉标签页都不丢，重新打开时提示「有未提交的改动」。
提交成功后草稿自动清掉。
⚠️ `localStorage` 被禁用或写满时会**静默降级**（改动只在内存里）—— 不能因为存不下草稿就让页面崩掉。

## 分词列表：纵向、时间可改

详情页朗读卡下面是一行一个词的列表（新增抽屉里同一套组件）：

```
本文 8 个单词                                  [重做标准音]
────────────────────────────────────────────────────────
Don't        [00:00.000] - [00:00.320]              ▶
count        [00:00.320] - [00:00.720]              ▶
```

⭐ **时间可以点开就地改**（回车确定 / Esc 取消 / 失焦也算确定），改完会立刻播一次 ——
改对没有，耳朵比眼睛快。三种写法都收：`00:01.590` / `1.590`（秒）/ `1590`（毫秒）。

⚠️ 为什么要留这条手工路：引擎对**弱读虚词**（the / to / is）给的边界经常落在**停顿**上
（实测 "the" 拿到过 80ms 的静音窗口），自动规则兜不住每一个。

⚠️ 词级时间也走**同一套**（输入框 + yes，没有单独的「试听」按钮 —— 先 yes 提交、
再点这一行的 ▶，语义更清楚）。改完的值一律进同一份「待提交」，
点底部的「更新」才一起提交（走 `PUT /api/articles/:id`，服务端**逐项校验**后才写正文 JSON）：

* 条数必须等于正文的切词数 —— 客户端只在 `words.length === 切词数` 时才启用点词播放，
  条数错了会**静默**退回预切切片（界面看起来正常，只是点词不再精确）；
* 每个词的 `word` 必须与正文第 i 个词一致（防止顺序错位）；
* 区间 ≥ **300ms**（`MIN_PLAY_SEC`，与流水线同一个常量）；
* 结束点不能越过音频时长 + 120ms（否则点它会播到空白）。

校验失败直接**报错**并指明是第几个词，不会写进去半个坏文件；
`content-files.test.ts` 里还有同样的断言在 CI 上兜底。

## ⭐ 音频接口必须支持 HTTP Range（别顺手删掉）

`GET /api/audio/<id>.mp3` 返回 `Accept-Ranges: bytes`，带 `Range` 时回 `206`。
**这不是省流量的优化，是「能不能 seek」的功能开关**：浏览器只有在服务端支持
range 请求时才把媒体标成 seekable，否则 `audio.seekable` 是 `[0,0]`，
给 `currentTime` 赋值会被**夹回 0** —— 症状就是「点词定位整个失效：
点哪个词都在播句子开头」。（实测：文件已完整 buffered，但 seekable 仍是 [0,0]。）

解析在 `apps/server/src/lib/http-range.ts`（纯函数，带测试）；
退回整份 200 也算正确，只是不能 seek。

## 界面与路由

| 路由 | 页面 |
| --- | --- |
| `/articles`（`/` 也归到这里） | 句库列表 |
| `/article/<id>` | 句子详情（朗读卡、行内编辑、分词列表、底部「更新」） |
| `/energy` | 能量（占位，还没做） |
| `/account` | 管理员账号（口令位置、各环境真实状态） |

用 history API 的前端路由，服务端对**没有扩展名的路径**回退到 `index.html`
（`/app.js.bak` 这种带扩展名的仍返回 404，免得写错资源名却拿到一份 HTML）。

列表列：`试听`（每行一个 ▶，播该句标准音）`｜英文原句｜译文｜难度｜发布时间｜状态｜详情`。
顶栏左边是「句拼 + 当前环境标识」，导航整体靠右。

## 为什么是「本地服务」，而不是塞进小程序

这个台子要干的事，全都是在写**内容生产**的产物：
改仓库里的正文 JSON、跑 fish 合成标准音、跑 LLM 出译文和难度、
往某个环境的 articles 表里落一行。

这些动作不该出现在用户端 —— 小程序连的是只读接口，
内容生产天生属于运维侧。所以它是：

* 一个本地进程（`tsx tools/admin/server.ts`），只监听 `127.0.0.1`，外部访问不到；
* 一个**手写的**单页前端（`web/`），没有构建步骤 —— 改完刷新就行；
* 登录用自建管理员账号（`ADMIN_USER` / `ADMIN_PASSWORD`，签名 cookie）。

## 数据的真相在哪（先看这段再改代码）

| 东西 | 真相 | 派生副本 |
| --- | --- | --- |
| 正文 / 译文 / 难度 / 标签 / 词级时间戳 | `content/articles/<id>.json` | `articles` 行、`articles.difficulty`、`article_tags` |
| 发布时间 | `articles.published_at` | —— |
| 标准音 + 逐词切片 | `content/audio/<id>.mp3`、`content/audio/<id>/w<i>.mp3` | 对象存储里的同名 key |
| 某天读哪句 | `schedules` 表 | —— |

* **id = `sha256(正文 trim 后)` 的前 16 位**（64 bit，长度见 shared 的 `constants`）——
  内容的 hash，同时是文件名、主键、音频路径。
  口径只允许有一个实现：`tools/pipeline/src/lib/article-id.ts`。
  所以**改 text 不是编辑，是新增一条**：id 变了，音频要重新生成，旧的那条还在。
* `articles.difficulty` 与 `article_tags` 是 `syncArticleIndex` 物化出来的**索引**，
  真相在 JSON 里。本台子写 JSON 之后会立刻同步一次索引，所以两边不会漂。
* `articles.published_at` 只在**草稿 → 已发布**那一刻写（迁移 `0029` 用 `created_at`
  回填了历史内容）。单纯改译文不刷新它 —— 它答的是「什么时候上的线」，
  不是「最后一次编辑」。`created_at`/`updated_at` 都答不了这个问题
  （后者没有 ON UPDATE 子句，实际等于前者）。

## 三个环境（local / dev / prod）

**在登录页选**（不是一个登录后随时可拨的开关）：环境只影响**写哪个库**，
内容文件永远写在本机仓库。

⚠️ 为什么放在登录页而不是顶栏：
这个台子的每个动作都会落到某个环境的库上（改译文、发布、排期、重生成音频），
**环境是这次会话的前提**。放登录页还有个实际好处 —— 选一个坏环境会**当场**失败
并说明原因，而不是登录成功之后句库空白 + 一行原始报错。
选定后写进 `.state.json`，下次登录默认还是它；要换环境就**退出后重新登录**。

| 环境 | 库 | 怎么连上 |
| --- | --- | --- |
| `local` | 本机 Docker 里的 MySQL | `.env.local` 的 `DATABASE_URL` |
| `dev` | 云托管 dev | 需要先在控制台**开启外网地址** |
| `prod` | 云托管 prod | 同上 |

按钮的可用性来自**一次真查询**（`probeDatabase` 连过去 `SELECT 1 FROM articles`），
不是「TCP 通了」——所以「云实例重建后库是一张白纸」（`Unknown database`）和
「库在但没跑迁移」（`Table doesn't exist`）都会显示成不可用并写明原因，
在「管理员账号」页能看到三个环境各自的真实状态。
连不上的原因也一并列出（`/api/envs` 会去查云托管 API 拿外网地址）。

⚠️ 环境是记在 `.state.json` 里的**全局**状态（单人操作台，不做 per-browser 会话）：
它是**登录页的默认选中项**；如果它已经用不了，登录页会把它标成不可用、
默认改选 local —— 而不是让人登录之后才发现句库是空的。

⚠️⚠️ **切到非 local 环境时，「正文 + 音频」都要等一次部署才到客户端。**
客户端读的不是库，是**镜像里的** `content/articles/*.json`（Dockerfile `COPY content`）
和对象存储里的音频；库里的 `articles` 行只是索引。具体到每种改动：

| 在后台做的 | 对 local | 对 dev / prod |
| --- | --- | --- |
| 改译文 / 难度 / 标签 | ✅ 生效（写本机正文 JSON） | ❌ **无效** —— 客户端读镜像里的 JSON，下次部署的 `reindexArticles` 还会按它覆盖回来 |
| 发布 / 下架 | ✅ 生效 | ✅ 生效（写库里的 `isActive`，部署不覆盖它） |
| 新增句子的正文 | ✅ 立刻可读 | ⏳ 要等部署；在那之前它**已经在库里、会被抽中排期** |

页面切到云环境时会把这三点直接写在抽屉顶部 —— 不写出来，运营会以为
「我改了译文，怎么线上没变」。

⚠️ **音频不进桶**：本台子只把音频写进本机 `content/audio/`，
进对象存储是**部署那一步**的事（dev 靠启动时的 `SEED_ON_START`，prod 手动灌）。
一个写入方比两个写入方好查 —— 两边各灌一次的话，
「线上听不到」这种问题会变成三个可能的原因。

⭐ 服务端为此做了兜底：`services/schedules.ts` 的轮转池会**跳过读不到正文的句子**，
所以「发布进库但没部署」不会让某一天的朗读页打不开（宁可池子小一点）。
用 `/health?deep=1` 的 `missingCount` 看这个差集。

## 新增一条句子的完整链路

1. 贴一句英文 → 点「跑生成流水线」（异步任务，进度实时打在页面上）
2. LLM 出 **译文 / 难度(0–3) / 标签**（带理由）；
   难度定不下来就**直接失败**，不猜（宁可不发，也不发一条档位错的）
3. fish 合成整句标准音 + 词级对齐 → 按 `wordRangesOf` 算出每个词的**播放区间**，
   写进 `content/articles/<id>.json` 的 `words[]`
4. 落一条**草稿**行（`isActive=false`）
5. 在页面上改译文/标签/难度，听整句、点词试听 → 点「发布」才 `isActive=true`

⚠️ 第 4 步的草稿行不是多此一举：`loadSeedArticles` 会扫 `content/articles/*.json`，
按 DB 默认值（`isActive` 默认 **true**）补插。只写文件不落行，
下一次部署它就自己上线了。

⚠️ 生成中途失败会**删掉刚写的正文文件** —— 同上，半成品文件留着 =
下次部署悄悄上线一句没有音、没有词的句子。

## 排期：**刻意不做在句子详情里**

句子详情回答的是「这一句内容本身」（正文/译文/难度/标签/发布状态），
而排期回答的是「哪一天展示哪一句」—— 两个层面的东西，混在一起会让人以为
「发布」和「排上某天」是同一件事。

所以详情页的 dl 里没有排期，编辑抽屉里也没有「排到这天」。
不排期的日子由 `scheduleAhead` 按天号**自动轮转**，这条链路完全不受影响。

⚠️ 服务端的 `POST /api/articles/:id/schedule` 仍然在（两条护栏也在：
草稿不能排、同日换题要带 `force`）—— 只是目前**没有界面入口**。
将来要做成独立的一页（或放回顶栏）时直接用它即可。

## 它不做什么

* 不改 `text`（改 = 新增）；
* 不删内容（删要连着音频、索引、排期一起处理，是独立的事）；
* 不碰对象存储（见上）；
* 不做评分 / 用户数据 —— 那是服务端和小程序的事。
