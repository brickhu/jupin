# 微信云托管约束（官方文档 + 实测）

> 决定「server 远程部署」方案时核实。**这些约束直接改变了音频上传的架构。**

---

## 一、⭐ 核心结论：音频必须走对象存储直传

| 通道 | 限制 | 用途 |
|---|---|---|
| **CallContainer**（小程序 → 云托管服务） | ⚠️ **大请求报 nginx 413**（文档写 100K） | 只传**小 JSON** |
| **对象存储**（`wx.cloud.uploadFile`） | ✅ **无大小限制**，支持分片 | **传音频** |

**算一下我们的音频：**

| 竞技场时长 | 16k/16bit/单声道 | base64 后 |
|---|---|---|
| 10 秒 | 320 KB | ~427 KB |
| **20 秒** | **640 KB** | **~853 KB** |

**远超请求体限制。**

### 官方社区的原话

> 问：云托管对象存储大小只有 1M 吗？这是云托管的限制吗？（附 413 截图）
> 答：是直接向云存储上传文件的？还是文件先上传云托管服务导致的报错？
> **如果直接向云存储上传文件，文件大小没有限制，可以使用分片上传。**

**「1M 限制」是「上传到云托管服务」的限制，不是对象存储的限制。**

另一位踩过同样坑的开发者给出的结论：

> 接口请求和响应，居然不能超过 1M……最终都需要经过一个中间对象存储的过程。
> 也就是**先将文件上传到云上，然后将对象的 id 作为接口入参传入**，后台需要时按 id 下载。

### 落地路径（已实现）

```
① 小程序 wx.cloud.uploadFile({ cloudPath, filePath })  →  拿到 fileID
② CallContainer 提交 { arenaId, fileID }               →  极小请求
③ 后端按 fileID 取回音频 → 调讯飞 → 返回结果
④ 评完分删除音频（隐私策略，可配）
```

**顺带拿到三个好处**：上传进度回调（`UploadTask.onProgressUpdate`）、用户音频可留存（支撑「点词回放」）、**免域名/免备案/免白名单**。

## 二、⭐ CallContainer：免域名、免备案、免白名单

官方原文：

> 小程序/公众号可使用 **CallContainer**，**无需域名**，因此**不需要在 mp 管理后台配置服务器域名**，从而一开始就**无需申请域名，也无需备案**。
> 小程序/公众号使用 CallContainer，后端服务可以**直接从 HTTP header 中获取 openid** 等信息。

**影响**：
- 自建服务器必须买域名 + ICP 备案 + 配小程序服务器域名白名单，**云托管这三样全免**
- **openid 直接从 header 拿** → 现有那套 `wx.login → code → jscode2session` 可以简化

**约束**：
- CallContainer **超时 ≤ 15s**（讯飞评测耗时必须远低于此）
- 请求体大小有限（见上）
- 可**关闭公网访问**，杜绝 DDoS

## 三、⚠️ 其他必须知道的约束（官方）

| 约束 | 影响 |
|---|---|
| **默认公网域名性能有限，仅接口测试用，禁止生产，且小程序后台无法配置** | 生产必须走 CallContainer 或已备案的自定义域名 |
| **容器不支持持久化存储** | 音频/内容必须用对象存储；容器重启会还原 |
| **一个服务只能开一个端口** | 多端口架构要拆服务 |
| 副本最小为 0 时，**半小时无请求缩容到 0**，再请求需冷启动（实测 9–30 s） | ⭐ **接受冷启动**：前端 `LAUNCH_BUDGET_MS = 50_000`（15s×3 + 退避）已覆盖它。最小副本设 1 是**常驻计费**（1核2G ≈2.86 元/天，见 §七）—— 2026-10-09 起 dev/prod 都是 0 |
| 云托管对公网域名**无 DDoS 防护** | 建议关闭公网访问 |
| **WebShell 里的修改不保留** | 任何代码变更都需重新构建部署 |
| 自带流量管理 | 无需额外配负载均衡 |

## 四、⚠️ 音频留存的合规要求

用户录音属于**个人信息**。⚠️⚠️ **现状与"评完分即删"相反**：`DELETE_AUDIO_AFTER_SCORE` 现在是 `false`（**永久保留**，只在检测失败时删；用户要求，见 `tools/deploy-cloud.mjs` 与 `apps/server/src/routes/submissions.ts`）。
⇒ 下面三条不是"将来的前提"，而是**现在已经欠着的义务** —— 是否已在小程序《用户隐私保护指引》声明"收集语音信息"、是否已给用户主动删除入口，**待确认**。

（历史口径："评完分即删"指的是 `DELETE_AUDIO_AFTER_SCORE=true`，已不再使用。）

若将来要做云端留存的「点词回放」，**必须同时满足**：
1. 在《用户隐私保护指引》中声明"收集语音信息"
2. 设定生命周期（如 N 天后自动清理）
3. 提供用户主动删除入口

**这不是可选项**——小程序对隐私接口有强制声明要求，未声明会直接调用失败。

## 六、⭐ 定时触发器（兜底清扫 + 连战提醒）

**它解决的是「兜底清扫兜不住」这件事** —— 这一条比"加个提醒功能"重要得多。

`apps/server/src/services/sweep.ts` 要修的两个洞，它自己的注释里写得很清楚：
**都不在"某次请求出错"，而在"没人来问"**：

| # | 洞 | 为什么惰性触发修不了 |
|---|---|---|
| ① | 悬空的 `scoring` 行 —— 用户提交完就退出、容器被缩容回收，那 2 点能量**既不全扣也不退回** | 心跳判死与接管**只在有入站轮询时**发生 |
| ② | 已出分但没结算 —— 分数看得见、能量扣了，但连战与饼干**全漏发且永不补** | `settle` 只跑一次（守卫 `cookies_earned IS NULL`） |

⚠️⚠️ 而它原来的触发方式是**惰性**的（进程启动一次 + 用户读数据时按节流跑一次）——
    **恰恰在"没人来问"的时候不跑**，也就是它要修的那两个场景 ✗
    ⇒ 定时触发器不是"锦上添花"，是**让这个兜底真的兜住**。

⚠️ `sweep.ts` 里写着「不引入定时器 —— 云托管上进程随时会被回收，**常驻定时器**
本来就不可靠」。那句反对的是 `setInterval` 那种**进程内的**定时器；
而云托管定时触发器是**平台级**的：到点起一个新实例、打一次接口 ✓ 不冲突。

### 配置（只能在微信云托管控制台做，`tools/deploy-cloud.mjs` 不管触发器）

1. 给服务配一个环境变量 `CRON_SECRET`（够长的随机串）
2. 控制台 → 定时触发器 → 新增：
   - Cron：`0 21 * * *`（每天 21:00，北京时间）
   - 请求：`POST https://<你的服务域名>/api/cron/sweep`
   - Header：`Authorization: Bearer <CRON_SECRET>`
3. ⚠️ 与 `ADMIN_TOKEN` 同一条规矩：**没配 = 503、配错 = 401**，绝不"没配就放行"
4. ⚠️ 用**专用**的 `CRON_SECRET` 而不复用 `ADMIN_TOKEN`：控制台里的口令更容易被看到，
   而两件事的爆炸半径差很远（前者只能触发一次幂等清扫，后者能发布/删除文章）

**已验证**：接口本身（`apps/server/src/routes/cron.ts`）。
**尚未验证**：控制台里配触发器这一步（需云环境就绪）。

## 七、⭐ 计费口径与实测（2026-10-09）

> 起因：用户问「dev 每天都在扣钱，不是个人版免费使用吗」。结论：**云托管没有"个人版/免费版"这个档位**，
> 只有「**首个环境 + 3 个月 + 额度内**」的一次性免费额度。以下全部来自官方定价页 / FAQ / 欠费说明 + `wxcloud` 实测。

### 7.1 计费模式

- 所有环境**按量付费**、先用后付、**每个环境独立计费**；系统**每日结算，次日扣费**（特殊情况下可能延迟，但不超过当月最后一天）。
- 账单入口：控制台 → **费用中心 → 充值与账单**（能看到逐项：容器 CPU/内存、构建时长、公网流量、MySQL 算力/存储、对象存储容量/次数/CDN、静态资源存储）。

### 7.2 免费额度（只有首个环境，只有 3 个月）

| 功能 | 参数 | 刊例价 | 免费额度（有效期 3 个月） |
|---|---|---|---|
| 容器 | CPU | 0.055 元/核·小时 | 720 核·小时 |
| 容器 | 内存 | 0.032 元/GB·小时 | 1440 GB·小时 |
| 容器 | 构建时长 | 0.05 元/分钟 | 600 分钟 |
| 容器 | 公网流量 | 0.8 元/GB | 5 GB |
| MySQL | 算力 | 0.342 元/个·小时 | 720 个·小时 |
| MySQL | 存储 | 0.00485 元/GB·小时 | 720 GB·小时 |
| 对象存储 | 容量 / 上传 / 下载 / CDN | 0.0043 元/GB·天 · 0.01 元/万次 · 0.01 元/万次 · 0.18 元/GB | 5 GB · 3000 万次 · 6000 万次 · 3 GB |
| 静态资源存储 | 容量 / 流量 | 0.0043 元/GB·天 · 0.21 元/GB | ⚠️ **无** |

⚠️ 官方 FAQ 明确列了三种「**没到 3 个月也扣费**」：① **创建了多个环境**（免费仅限首个，多建的**立刻计费**）；② **开通了静态资源存储**（无免费额度）；③ 容器规格过大 / 用量提前超额度（用到 80% 会推消息）。

### 7.3 本项目实测

| | prod（首个环境） | dev（多建的那个） |
|---|---|---|
| 环境创建 | 2026-01-21 **10:45:01** | 2026-01-21 **10:48:12** |
| 免费额度 | 有，但 **2026-04-21 到期** | ⚠️ **从来没有**（多建的环境立刻计费） |
| 服务 `jupin` | 1 核 2 G · minNum **0** · max 5 · MySQL 已开 600 s 自动暂停 | 同左（**2026-10-09 由 minNum=1 改 0**） |

- 1 核 2 G 常驻 = 0.119 元/小时 = **2.86 元/天 ≈ 86 元/月** ← 这就是当时"每天都在扣钱"的全部原因。
- 0.25 核 0.5 G = 0.0298 元/小时 ≈ 0.71 元/天（降规格可行：实测能起来；但 0.5 G 对 ffmpeg + Node 偏紧，dev 最终保留 1 核 2 G + minNum 0）。
- **改不了的部分**：MySQL 存储（dev 已用 0.043 GB ⇒ ≈0.005 元/天）、对象存储容量（`DELETE_AUDIO_AFTER_SCORE=false`，录音永久保留 ⇒ 桶会涨）。MySQL 算力可靠自动暂停归零（闲置 10 分钟）。
- **不在云托管账单里的按量成本**：讯飞 ISE（`ENGINE=xfyun`，每试读一次真计费）、大模型点评（`LLM_*`）、现网虚拟支付（`XPAY_ENV=0`，dev 测试充值也是真钱）。

### 7.4 操作注意

1. 改规格 / 副本数：`wxcloud service:config update -e <envId> -s jupin -c <核> -m <GB> -n <最小> -x <最大> --cpuThreshold 60 -l stdout --noConfirm`。
   - 规格只能按官方搭配：0.25/0.5 · 0.5/1 · 1/2 · 2/4 · 4/8 · 8/16 · 16/32。
   - 改配置会**自动发布一个新版本**（沿用最后一次版本的代码）；**发布中再改会报 `ResourceInUse`**。
   - 部署本身**先起 1 个实例**，成功后等半小时才可能缩容 ⇒ 每次部署都有约 30 分钟的容器消耗。
2. ⚠️⚠️ **别裸跑 `wxcloud service:config read/update`** —— 它会把**整套 `envParams`（含明文密钥）**打进 stdout。
   2026-10-09 实际发生过两次：一次是 `service:config update`（TOKEN_SECRET / WX_SECRET / XPAY_APP_KEY / LLM_API_KEY / XFYUN_* / ADMIN_TOKEN / CRON_SECRET 全部回显），
   一次是 `pnpm deploy:dev` 的"服务参数"确认表（同样明文）。**本机没有 CI 的 `::add-mask::` 兜底** ⇒ 重定向出来的 `.tmp/*.log` 就是一份明文密钥副本，用完删掉。
   要查就自己过滤（只打印 cpu/mem/minNum 与 env 的键名/哈希）。
   ⚠️ 还有：`service:config read` 的 `envParams` 会**滞后**（改完密钥后仍报旧值）—— 判据要打接口（如拿新 `ADMIN_TOKEN` 调 `/api/admin/articles` 看是否 200），别只看回显。
3. ⚠️ **欠费红线**（官方）：欠费 12 h 内正常使用且继续扣费；**12 h ~ 7 天所有环境停服**（数据库/对象存储/静态资源存储**继续扣费**）；**超过 7 天资源销毁 —— 账号下所有环境被删除，无法找回**。
