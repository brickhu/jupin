# 内容生产调研

> 素材库（竞技场）生产流程所需的三个外部依赖：TTS + 词级时间戳、词典数据、朗读难度定级。

---

## 一、TTS 与词级时间戳 —— fish-audio ✅

**结论：fish-audio 原生支持词级时间戳，正好是素材库最需要的东西。**

接口：POST /v1/tts/stream/with-timestamp

```json
{
  "content": "Hello world",
  "chunk_seq": 0,
  "chunk_audio_offset_sec": 0.0,
  "alignment": {
    "audio_duration": 0.86,
    "segments": [
      { "text": "Hello", "start": 0,    "end": 0.42 },
      { "text": "world", "start": 0.42, "end": 0.86 }
    ]
  }
}
```

**segments 就是词级时间戳**，官方文档自己的用途说明是「karaoke-style highlighting, word or phrase progress indicators」。

**一个接口同时解决两件事**：标准发音音频 + 每个词在音频里的位置。

### ⭐ 为什么时间戳是硬需求

「逐词 A/B 对比」需要**双方都有词级时间戳**：

| 音频 | 时间戳来源 | 状态 |
|---|---|---|
| 标准发音 | fish-audio alignment.segments | ✅ |
| 用户录音 | 云端评分结果（讯飞 beg_pos/end_pos，单位 10ms） | ✅ |

**不存时间戳，点词功能就是错的。**

### ⚠️ 音频策略

**整篇 + 每个竞技场各生成一份。**

理由：用户实际是**独立读一个句群**的，竞技场标准音也应独立生成——**韵律条件一致，A/B 对比才公平**。TTS 成本可忽略。

### ⚠️ 最容易踩的坑：分词对齐校验

fish-audio 返回的 segments[].text 是它自己切的词，必须与自建词表**逐项一致**，否则时间戳对不上。

常见差异：缩写（don't vs do + n't）、标点（dress, vs dress）、连字符、数字。

**必须做严格校验：**

```
比对 segments.length === words.length
且逐项比对 text（去标点、统一小写后）
不匹配 → 标记出来人工修正或重新合成
```

**而且切词规则须与评分引擎一致**（讯飞有明确的官方分词分句规则，见 ise-probe-report.md）。

## 二、词典数据 —— ECDICT ✅

**结论：一个 MIT 协议的开源英汉词典，同时覆盖音标 + 词性 + 义项 + 词形变化 + 难度标签。**

skywind3000/ECDICT — **MIT 协议（可商用）**，约 **76 万词条**，有 npm 包与 SQLite 版本（建议转 SQLite，查询远快于读 CSV）。

| 字段 | 内容 | 用途 |
|---|---|---|
| phonetic | **音标** | ⭐ 音标（**绝不能让 LLM 生成**） |
| pos | **词性**（/ 分隔多词性） | 词级数据 |
| translation | **中文释义**（全部义项） | 词级数据 |
| definition | 英文释义 | 可选展示 |
| exchange | **词形变化** | 词典查找还原 |
| tag | **考试标签**（zk/gk/cet4/cet6/ky/toefl/ielts/gre） | ⭐ 难度定级参考 |
| collins / oxford | 柯林斯星级 / 牛津核心词 | 难度参考 |
| bnc / frq | 语料库词频 | 难度参考 |
| lemma | 原型 | 词形还原 |

### ⭐ 关键设计：让 LLM 从「生成」降级为「选择」

```
❌ 原来：LLM 输入句子 + 单词 → 输出音标 + 词性 + 释义   （从零生成，会编）
✅ 修正：ECDICT 查出音标 / 词性 / 全部义项
        → LLM 只回答「在这句话里哪个义项对，用 5–15 字精简」
```

| | 从零生成 | 从义项里选 |
|---|---|---|
| 幻觉风险 | **高** | **低**（有权威依据） |
| 音标 | 可能错且难发现 | **不用 LLM，直接查表** |
| 成本 | 每次生成 | 输出更短，更便宜 |

**⚠️ LLM 生成的音标会幻觉，而且你很难发现。音标必须查词典。**

## 三、朗读难度定级

### ⚠️ 核心区分：「朗读难度」≠「阅读难度」

| 维度 | 阅读难度 | **朗读难度** |
|---|---|---|
| 词汇生僻 | ✅ 主要 | ⚠️ 次要 |
| 句法复杂 | ✅ 主要 | ⚠️ 次要 |
| **语音难点密度** | ❌ 无关 | ✅ **主要** |
| **连读/弱读密度** | ❌ 无关 | ✅ **主要** |
| **长度/气息** | ⚠️ | ✅ 主要 |

**极端例子：**

> "The sixth sick sheikh's sixth sheep is sick."
> 所有单词都是高考及以下词汇 → 按词汇算难度是 ⭐
> **但这是公认的英语最难绕口令**（/s/ /ʃ/ /θ/ 在 8 个词里反复切换）→ 真实朗读难度 **⭐⭐⭐⭐⭐**

**若按词汇定级，绕口令会被标成最简单的一档 → 「征服 ⭐」失去含金量 → 整个征服体系崩塌。**

### 方案：脚本算特征 → LLM 综合判断 → 人工审核

> ⚠️ **2026-09 已废弃上面这条「脚本算特征」的路** —— 难度改为**全由 LLM 判**（见 spec.md 第九节）。
> 下面这张特征表**保留为调研记录**（它说清了难点在哪），但流水线不实现它，别照着做。

**喂给 LLM 的客观特征**（脚本计算）：

| 特征 | 说明 |
|---|---|
| **难音密度** | 含 /θ/ /ð/ /v/ /w/ /l/ /r/ 及长短元音对立的词占比 ⭐ 最强预测因子 |
| **连读点数量** | 词尾辅音 + 下词首元音 |
| **弱读功能词数量** | 中国学习者的主要失分点 |
| 词数 / 音节数 | 气息和长度 |
| 最长词音节数 | 单词本身难度 |
| 句法复杂度 | 次要 |
| ECDICT 词汇难度 | 次要 |

**⭐ 锚点是关键**：必须提供 **5–10 条人工已定级样本**作为参照，覆盖 ⭐ 到 ⭐⭐⭐⭐⭐。
**没有锚点，LLM 的星级标准会漂移**（同一句今天 ⭐⭐⭐、明天 ⭐⭐）。

> ✅ 2026-09：锚点**已采用** —— 而且是被实测逼出来的：
> 只给四档文字描述时，重判 8 句有 **7 句上移、5 句挤在「高级」**；
> 加上**每档一句参照样本**后，分布变成 **初级 1 / 中级 2 / 高级 3 / 专家 2**。
> 上面这条结论**被实测证实了**。样本见 tools/pipeline/src/lib/article-meta.ts 的 SYSTEM。

**稳定性措施**：temperature 设 0–0.2 · 定级一次即固化入库 · 人工审核后锁定。
**输出要求**：stars + **reason**（可解释，人工审核时一眼能判断对错）。

### 必须抽查的两类易错

| 易错类型 | 例子 |
|---|---|
| 词汇难但朗读不难 | "The utilization of sophisticated methodologies…" → 别被长词骗 |
| ⭐ **词汇简单但朗读极难** | 绕口令 → **最容易漏判，且漏判是致命的** |

## 四、朗读技巧生成

### ⚠️ 不能让 LLM 自由发挥

LLM 的语音学判断不可靠：会编造不存在的连读、漏掉真正的难点、拼错音标。**而技巧是用户会照着练的东西——错了就是教错。**

### 正解：规则检测 → LLM 润色 → 人工审核

**第一步：规则检测**（脚本，零成本，精确）

| 技巧类型 | 检测规则 | 数据来源 |
|---|---|---|
| **连读** | 词尾是辅音 + 下一词首是元音 | 音标（ECDICT） |
| **弱读** | 匹配固定功能词表（a/an/the/at/to/for/of/and…） | 词表 |
| **难音** | 音标含 /θ/ /ð/ /v/ /w/ /l/ /r/ /iː/ /ɪ/ /uː/ /ʊ/ | 音标（ECDICT） |
| **词尾辅音** | 词尾辅音后无元音，且是多音节词 | 音标 |
| **重音** | 3 音节以上的词 | 音标 |
| **语调** | 句末标点（. 降调，? 升调） | 文本 |

**这些都是确定性规则，不会编。**

**第二步：LLM 只做润色**——挑 1–3 条最值得说的，用自然中文写出（每条 20–40 字），**约束：只能针对已检测出的点，不得新增**。

**第三步：人工审核**（内容量小，可行；前 50 句建议 100% 过一遍）。

### ⭐ 技巧应配示范音频

用词级时间戳精确切出对应短语的音频：

```
① looked at 连读，读成 /lʊktət/        [▶ 听这句]
② the / to / of 要弱读，别读太重        [▶ 听这句]
```

**「听短语的标准读法」比「看音标」有用得多**——大部分中文用户看不懂 IPA，**文字 + 示范音频是主体，音标只是辅助**。

### ⭐ 技巧不该是静态展示

**真正的用武之地是重录循环里的兜底：**

```
预检失败 → "girl 这个词没听清，再读一遍试试"
        → 💡 girl 的 /ɜːr/ 要卷舌到位  [▶ 听示范]
        → [ 重录 ]
```

**用户不会主动去读技巧，但他在卡住的那一刻一定会看。**
