## 一、产品内核

**以句子竞技场为单位，以短文为内容载体。**

> 一个产品要做两件事：让用户有东西可读（短文），让用户有对手可比（竞技场）。

---

## 二、两层结构 ⭐

**内容单位 ≠ 竞技单位。这是整个设计的地基。**

```
┌─ 短文（内容单位，100–300 词）──────────────────┐
│  · 全文 + 中文翻译                               │
│  · 整篇标准音（fish-audio，带词级时间戳）          │
│  · 可听、可读、可理解                            │
│                                                 │
│  其中切分出 3–5 个「竞技场」（自然句群，10–20 秒）  │
│    ├─ 竞技场 1  ⭐⭐      1,284 人竞技            │
│    ├─ 竞技场 2  ⭐⭐⭐⭐    892 人竞技             │
│    └─ 竞技场 3  ⭐⭐⭐     1,057 人竞技            │
└─────────────────────────────────────────────────┘
                    ↓ 选一个竞技场
        录音（10–20 秒）→ 本地预检 → 提交检测 → 上榜
```

### 为什么必须分两层

| 若用整篇做竞技单位 | 后果 |
|---|---|
| 重录成本 | 读错一个词要重读 80 秒 → **核心循环崩溃** |
| 成本 | SOE 按文本长度计费，200 词 = 10 次调用 = **¥0.05/次**（贵 10 倍） |
| 竞技场密度 | 门槛高、耗时长 → 榜单稀疏 |

| 分层后的收益 |
|---|
| 重录无痛（10–20 秒） |
| 每次提交仅 1 次调用（约 20 词） |
| 一篇短文产出 3–5 个竞技场 → 密度有保障 |
| 同一篇短文内可有不同星级的竞技场 |
| 内容有语境、有价值、有话题性 |

## 三、用户只有两个动作

| 动作 | 成本 | 后果 | 限制 |
|---|---|---|---|
| **录音 / 重录** | 本地 | 无后果，不进榜，不消耗任何东西 | **无限** |
| **提交检测** | 云端 | 进榜 · 消耗 24h 冷却 | 每 24h 1 次（免费） |

**没有"练习模式"，也没有"竞技模式"。**

"练习"不是一种模式，它**就是带着反馈的重录这个动作本身**。

            [ 云端评分 ] → 上榜 → 24h 冷却                    │
                                                             └──► 回到 [ 待录音 ]
```

## 五、本地预检（放行标准）

**目的**：不达标的内容不得进入竞技场，也不消耗云端成本。

| 层 | 判据 | 动作 |
|---|---|---|
| **① 技术有效性** | 时长达标、检测到语音活动、能量正常 | 硬拦 |
| **② 长度合理性** | 有效语音时长 < 预期时长的 50% | 硬拦 |
| **③ 可识别性** | ASR 识别出的英文词 ≈ 0 | 硬拦 + 给技巧 |

**关键原则**：
- 判定标准是**「能不能被听懂」**，不是**「读得标不标准」**
- 语速基准 **150 wpm**（每词约 0.4 秒），读得慢不会被拦，只有明显没读完才拦
- 阈值一律**极度宽松**：放行垃圾的成本是 ¥0.005，误伤用户的成本是流失
- 失败时**保留"重新检测"出口**（应对网络/服务异常，避免死锁）
- **反馈粒度**：竞技场是 10–20 秒，逐词反馈可接受（不会变成噪音）

**技术实现**：纯信号处理 + 免费原生能力（VAD / 能量 / ASR），**不需要本地模型**。

## 六、指标体系

### 横向：竞技场

```
87 分
第 16 名 / 1,284 人
```

### 纵向：两层进步

| 层次 | 表达 | 本质 |
|---|---|---|
| **① 单句刷新** | `🎉 62 → 87` | 熟悉度——我把这个竞技场练熟了 |
| **② 难度征服** | 我能征服到 ⭐⭐⭐⭐ | **真实能力——边界外扩了** |

### 征服

> **在该竞技场拿到 ≥ 85 分 = 征服。永久保留，只增不减。**

- **统一阈值**，不按难度分级（星级已天然分层）
- 用**绝对分**判定，不用排名（排名依赖别人，成就不能依赖别人）
- 只有云端分可参与征服判定

### 难度星级

**标在竞技场上**（不是短篇上）。短文显示星级范围（如 ⭐⭐ ~ ⭐⭐⭐⭐）。

| 内部 D | 对外 |
|---|---|
| 1.0–1.5 | ⭐ 入门 |
| 1.5–2.5 | ⭐⭐ 简单 |
| 2.5–3.5 | ⭐⭐⭐ 中等 |
| 3.5–4.5 | ⭐⭐⭐⭐ 困难 |
| 4.5–5.0 | ⭐⭐⭐⭐⭐ 挑战 |

### 个人主页：能力边界

```

⭐⭐⭐⭐    ███░░░░░░░   3   ← 你在这里

## 七、付费模型

### 免费额度

- 每 **24 小时 1 次**提交检测
- **滚动冷却**（`next_free_at = last_submit_at + 24h`），**不是自然日重置**
- 时间戳存服务端，客户端只做展示

### 会员

| 方案 | 价格 | 折算 |
|---|---|---|
| 包月 | **¥19.9** | ¥19.9/月 |
| 包年 | **¥199.9** | ¥16.7/月，省 16% |

**权益**：无限次提交检测，不用等待。

### 付费触发（唯一主路径）

**用户点击「提交检测」时弹窗**，不是首页倒计时。

```
┌────────────────────────────────────┐
│  ⏳ 挑战冷却中                       │
│                                    │
│  你距离 Mike 只差 2 分               │   ← 先唤醒动机
│                                    │
│  下次免费挑战还需等待                 │
│  23:47:12                          │
│                                    │
│  ┌──────────────────────────────┐  │
│  │  成为会员，立即挑战            │  │
│  │  不限次数 · 不用等待           │  │
│  └──────────────────────────────┘  │
│              等一等                 │
└────────────────────────────────────┘
```

**要点**：先说动机 → 再说阻碍 → 最后给解法；底部弹层；保留"等一等"出口。
**次要路径**：按钮常驻 `[ ⏳ 23:47:12 后可提交 ]`。

### 无效提交

```
有效上榜      → 消耗 24h 冷却
判定无效      → 不消耗冷却，计入"无效次数"
无效次数 ≥ 3  → 当天暂停提交
```

## 八、数据模型

```sql
-- 短文（内容单位）
passages
  id, title, content, translation
  stars_min, stars_max        -- 展示用范围
  topic_id
  full_audio_url, full_audio_duration_ms
  is_active, published_at

-- 竞技场（竞技单位 = 句群）
arenas
  id, passage_id, position
  content                     -- 句群文本
  word_start, word_end        -- 在短文中的词区间
  stars                       -- ⭐ ~ ⭐⭐⭐⭐⭐
  audio_url                   -- ⭐ 独立生成的标准音
  audio_duration_ms
  expected_speech_ms          -- 用于本地预检第②层

-- 词级数据
arena_words
  id, arena_id, position
  word, ipa, pos, meaning_zh
  start_ms, end_ms            -- 词在竞技场标准音中的位置

-- 朗读技巧
arena_tips
  id, arena_id
  type                        -- linking/weak_form/stress/intonation/pause/difficult_sound
  word_start, word_end        -- 用于高亮
  note_zh, ipa
  audio_start_ms, audio_end_ms -- ⭐ 针对性示范音频区间
  sort

-- 成绩
arena_entries
  id, arena_id, user_id
  score, rank_snapshot, beaten_count
  is_conquered                -- score >= 85
  created_at
```

**音频策略**：短文和每个竞技场**各生成一份标准音**。
- 整篇音频 → 用于试听全文（韵律连贯）
- 竞技场音频 → 用于竞技对比与逐词示范（与用户独立朗读的条件一致）

TTS 成本可忽略，但**韵律匹配对 A/B 对比至关重要**。

## 九、内容生产流程

```
① 选文（人工）
   来源：名言集 / 演讲节选 / 短篇散文
   ⚠️ 影视台词、歌词有版权风险，慎用

② 切分竞技场（LLM 提案 → 人工确认）
   原则：语义完整 · 时长 10–20 秒 · 在自然停顿点切 · 每篇 3–5 个

③ 朗读难度定级（脚本算特征 → LLM 判断 → 人工审核）
   ⚠️ 是「朗读难度」，不是「阅读难度」
   特征：难音密度 / 连读点数 / 弱读词数 / 词数与音节数 / 最长词音节数
   锚点：5–10 条人工已定级样本（校准标尺）
   输出：stars + reason（可解释）

④ 标准音 + 词级时间戳（fish-audio /v1/tts/stream/with-timestamp）
   整篇一份 + 每个竞技场一份

⑤ 整篇翻译（LLM）

⑥ 音标 / 词性 / 义项（ECDICT 查表，MIT 协议，76 万词条）
   ⚠️ 音标绝不能让 LLM 生成

⑦ 词级释义（ECDICT 给义项 → LLM 选语境义 → 人工审核）
   LLM 从「生成」降级为「选择」，避免幻觉

⑧ 朗读技巧（规则检测 → LLM 润色 → 人工审核）
   连读：词尾辅音 + 下词首元音（规则可判）
   弱读：固定功能词表
   难音：音标里含 /θ/ /ð/ /v/ /l/ /r/ 及长短元音对立
   LLM 只负责把检测到的点写成自然中文，不得新增

⑨ 对齐校验 + 入库
   ⚠️ fish-audio 返回的 segments[].text 必须与自建词表逐项一致
      不一致则人工修正或重新合成
```

**人工不可替代的三件事**：选文、审核、抽查。

## 十、已删除的概念

| 概念 | 原因 |
|---|---|
| 能力分 P | 公式用户看不懂；"超过多少人"是更好的翻译 |
| 经验分 E | 白送的投入度，无成就感，诱导刷量 |
| 质量分 Q（对外） | 降级为竞技场原始分数 |
| 难度系数 D（对外） | 改为星级标签 |
| CEFR 等级 / 6 个称号 | 抽象，与竞技场语言不一致 |
| 三条曲线 | 由「能力边界图 + 单场打磨史」取代 |
| 总积分 | 累加值无意义；**绝不能做排行榜**（会退化成经验分） |
| 平均击败百分位 | 零和指标，分母会动，看不到真实进步 |
| 练习模式 / 竞技模式 | 用户只有两个动作 |

**用户需要理解的概念只有三个**：第几名 · 刷新 · 征服。

## 十一、技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| **平台** | ⚠️ 待定（小程序 / 原生客户端） | 见第十三节 |
| **录音** | `getRecorderManager` + PCM 16k 单声道 | 或原生 AVAudioEngine / Oboe |
| **本地预检** | 信号处理（VAD/能量）+ ASR（微信同声传译插件 / 系统原生） | **无需模型** |
| **评分引擎** | ⚠️ **需重新评估** | 见下 |
| **标准音** | **fish-audio**（原生词级时间戳） | 已确认 `segments[{text,start,end}]` |
| **词典数据** | **ECDICT**（MIT，76 万词条） | 音标/词性/义项/词形变化/考试标签 |
| **后端** | Node + Hono + PostgreSQL | 需支持 WebSocket（若做流式） |

### 引擎候选对比

| 引擎 | 词级 | 分句级 | 音素级 | 行为异常检测 | 实时流式 | 单价（20 词） | 免费额度 |
|---|---|---|---|---|---|---|---|
| **科大讯飞 ISE** | ✅ | ✅ 原生 | ✅ | ✅ **11 类** | ❌ 实测为零中间结果 | **¥0.00387** | **10 万次** |
| 腾讯云 SOE | ✅ | ⚠️ 未实测 | ✅ | ⚠️ | ⚠️ 断句中间结果（未实测） | ¥0.005 | 无 |
| 驰声 Chivox | ✅ | ✅ | ✅ | ⚠️ | ✅ **宣称支持** | ≈¥0.027 | 600 次 |

### ⚠️ 讯飞 ISE 接入细则（踩坑清单）

> 这一节记录的都是"不知道就会再踩一次、而且踩了很难查"的坑。

#### 坑 1：不传 `ise_unite=1` 会拿到 0–5 分制（不是百分制）

流式版文档有「评测返回结果与分制控制」参数：

| 参数 | 默认值 | 说明 |
|---|---|---|
| `rst` | `entirety` | 返回结果与分制控制 |
| `ise_unite` | **`0`** | **返回结果控制** |
| `plev` | `0` | 返回字段详细程度（`plev=0` 时英文返回 accuracy/serr_msg/syll_accent/fluency/**standard_score**/**pitch**） |

文档原文：**「英文百分制推荐传参（`rst="entirety"` 且 `ise_unite="1"` 且配合 `extra_ability` 参数使用）」**

**必须同时满足三个条件才能拿到 0–100：**

```js
business: {
  rst: 'entirety',              // 默认即有
  ise_unite: '1',               // ⚠️ 默认是 0，必须显式传
  extra_ability: 'multi_dimension',
}
```

**只传 `extra_ability` 不传 `ise_unite` → 得到 0–5 分制**，`total_score` 形如 `4.795611`。

⚠️ **另一个陷阱**：网上容易搜到的《语音评测 API 文档》（`docs/voiceservice/ise/API.html`）是**普通版**的文档（2020-08 已下线），其示例分制与流式版**不同**。照那份文档写代码会踩坑。

#### 坑 2：必须加分值断言

```js
// 拿到分数后立即断言，防止分制回归
if (!(score >= 0 && score <= 100)) throw new Error('ISE 分制异常: ' + score)
```

**一条断言就能防住这个 bug**，且成本为零。

#### 坑 3：`integrity_score` 是乘性因子，漏读惩罚极重

成人句子总分公式（文档明确给出）：

```
total_score = (0.5 × accuracy_score
             + 0.3 × fluency_score
             + 0.2 × standard_score) × integrity_score
```

篇章版为 0.6 / 0.3 / 0.1。

⭐ **这意味着完整度是乘性的，不是加权项**——准确度再高，只要漏读导致完整度下降，总分会被成比例拉低。

**对设计的直接影响**：UI 上「漏读」必须与「发音不准」区别表达（漏读用灰色删除线，不用红色），本地预检第②层（长度合理性）本质上是在保护用户不被完整度重罚。

#### 坑 4：其他需要知道的字段

| 字段 | 含义 |
|---|---|
| `beg_pos` / `end_pos` | **单位：帧，每帧 10ms** |
| `word.dp_message` | 0 正常 / 16 漏读 / 32 增读 / 64 回读 / 128 替换 |
| `syll.syll_score` | 音节得分 |
| `syll.serr_msg` | 音节检错（1 或 2049 = 朗读错误；2049 = 音节与重音皆错） |
| `syll.syll_accent` | 重读检错（1 = 该音节需要重读） |
| `word.pitch` | **逐帧音高** ⭐ 语调曲线的免费数据源 |
| `is_rejected` | 是否被拒（无有效语音） |

**已知但暂不可用**：word 层有 `property` 与 `werr_msg` 字段用于**停顿/连读/重读/句末升降调检错**，但官方标注"效果优化中，无需关注"。**P2 再评估。**

#### 坑 5：其他

- **音频格式不符会被判"乱读"，且分值不可参考**——务必严格 16k / 16bit / 单声道 PCM
- **WebAPI 并发 50 路**；音频时长上限约 2 分钟
- **音标是「讯飞音标」，不是国际音标**，有细微差异（影响素材库音标对照，见第七节）
- IP 白名单未配置会返回 `10105 illegal client_ip`
- `X-CheckSum` 有效期 5 分钟，需与标准时间同步

| # | 验证项 | 影响 |

## 十三、平台决策依据（未决）

| 方案 | 优势 | 代价 |
|---|---|---|
| **微信小程序** | 传播链路短、支付现成、获客门槛低 | 本地推理能力弱、端侧模型难落地 |
